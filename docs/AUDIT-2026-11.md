## 3. Sécurité : revue STRIDE

| Surface | Menace | Protection en place |
|---|---|---|
| Formulaire | Spam, robots (D) | Turnstile + champ piège + 3 envois / 10 min par IP + tailles max (Zod et base) |
| Formulaire | Données invalides (T) | Zod côté serveur ; choix acceptés = listes publiées dans Studio (fail-closed) |
| Formulaire | Fuite (I) | Aucune lecture publique (RLS) ; IP hachée ; succès affiché seulement après insertion |
| Courriels | Injection HTML / en-têtes (T) | Contenu échappé ; objets sur une ligne ; envoi par API JSON (pas de SMTP brut) |
| Admin | Usurpation (S) | Lien magique à usage unique ; `shouldCreateUser: false` ; réponse identique pour toute adresse |
| Admin | Élévation (E) | `requireAdmin()` à chaque page et action + RLS `is_admin()` en base ; un compte non-admin est refusé (test E2E) |
| Admin | Traçabilité (R) | Journal des statuts et anonymisations dans `quote_messages` (auteur, date) |
| Données | Loi 25 | Consentement horodaté + version ; anonymisation manuelle et automatique à 24 mois (pg_cron) |
| Site | Clickjacking, XSS (T) | `frame-ancestors 'self'`, CSP, pas de `dangerouslySetInnerHTML` sauf JSON-LD échappé |

## 5. Recommandations restantes (par ordre d'impact)

1. **Avant la mise en ligne (bloquant)** : remplacer dans Studio les 12 valeurs d'exemple (`pnpm check:placeholders`),
   faire relire la politique de confidentialité et les conditions, nommer le responsable Loi 25.
2. **Contenu qui convainc** : ajouter de vrais extraits de modèles / plans (anonymisés) dans le bloc « Exemples de livrables »
   et en illustration des pages de service. C'est le levier n° 1 de crédibilité ; la structure est prête.
3. **Performance (−9 Ko)** : en production, remplacer la mise à jour en direct pour les visiteurs par le webhook de
   revalidation Sanity (prévu en phase M) et garder le direct seulement dans l'aperçu Studio.
4. **CSP plus stricte** : passer à des scripts avec *nonce* au lieu de `'unsafe-inline'` (demande un rendu dynamique ;
   à évaluer contre la perte du pré-rendu statique).
5. **Édition visuelle** dans Studio (cliquer un texte du site) : ajouter un jeton Sanity *Viewer*.
6. **Tests E2E sur le build de production** (plus stables qu'en dev) dans la CI GitHub (phase M).
7. **Turnstile** : la clé publique doit être présente **au build** sur Netlify (le formulaire est pré-rendu).
8. **Conservation** : la durée (24 mois) est fixée dans la tâche pg_cron ; le champ « Conservation » de Studio est
   informatif. Si elle change, modifier aussi la migration.
9. `minimatch` (1 alerte modérée, outil CLI de Sanity uniquement) : surveiller une mise à jour de Sanity.
